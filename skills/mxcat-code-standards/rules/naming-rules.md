# 命名规范

## 适用范围

- 仅在项目中无明确命名风格时依照该 skill 中的命名规则进行命名
- 如果仓库在某个目录层级已经形成稳定命名风格，则新增文件和目录必须沿用该风格，不得在同一层再引入第二套命名系统。

## 规则

- 大驼峰（PascalCase）：组件、类、接口与类型别名一般使用此形式。泛型参数一般使用大驼峰，或使用单个大写字母。
- 小驼峰（camelCase）：变量、参数、函数、方法以及对象的一般属性一般使用此形式。
- `UPPER_SNAKE_CASE`：模块级、且声明后不再重新赋值的常量一般使用此形式。
- 全小写连字符：新建目录一般使用此形式；名称由多个词组成时，词与词之间一般以 `-` 连接。
- `useXxx`：自定义 Hook 的文件名与导出函数名一般使用此形式。
