# 导入规范

## 执行原则

- 仅改 `import` 相关顺序、分组、空行、格式以及删除确认未使用的导入
- 保持最小 diff。

## 规则

1. 按命名风格分组

- 分组顺序：`PascalCase` -> `camelCase` -> `UPPER_SNAKE_CASE`。
- 组间保留 1 个空行。

2. 子组内排序

- 每个值导入或类型导入子组内，先放单行 import，再放多行 import；单行区与多行区之间保留 1 个空行。
- 单行 import 按整行字符长度从长到短排序；若长度相同，按主要导入成员名字母序（A-Z）排序。
- 多行 import 块放在对应子组的单行 import 区之后；多行块之间保留 1 个空行。
- 多行 import 块之间按主要导入成员名字母序（A-Z）保持稳定顺序。
- 多行 import 块内部成员按成员名长度从长到短排序；成员名长度相同按字母序（A-Z）。
- 存在初始化依赖、裸副作用导入等放在最后。

3. 值导入与类型导入

- 同一命名组内，值导入必须位于 `import type` 之前；值导入和类型导入各自作为一个排序子组。
- 每个排序子组继续适用“单行在前、多行在后”和对应的长度、成员排序规则。
- 值导入与类型导入之间不额外拆分空行。

4. 单行成员规则

- 单行 `import { ... } from '...'` 内成员按成员名长度从长到短排序。
- 成员名长度相同按字母序（A-Z）。

5. 未使用导入清理

- 可移除已确认未使用的成员。删除最后一个运行时绑定或整条导入前，还需确认不会丢失必要的模块执行；已确认无必要副作用才删除整条导入。
- 不删除仍有必要的裸副作用导入，也不借整理改变初始化顺序。
- 不为了“看起来整洁”删除用途不明确、由装饰器 / 宏 / 构建插件隐式消费，或无法在当前上下文确认的导入。

6. 约束

- 不改路径别名与路径文本。
- 不改默认导入、命名导入、类型导入的语义。
- 不引入 lint 无关重构。
