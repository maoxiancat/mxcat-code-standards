# mxcat-code-standards

## 安装

安装与验证见本技能目录 [README.md](README.md)。

## 启用

只执行本文件列出的约束。路径别名，以及 Prettier 已经决定的换行，跟目标仓库的现有写法。

- 只约束本次新写的代码。会新增文件、新职责或新的公共出口时，先按「架构」定落点，再写实现，再按「代码」整理新写的部分。
- 只改现有函数内部、且没有新增职责：跳过「架构」。不为此移动代码、拆分文件或新建目录。
- 旧文件只为接上新代码时，加导入和使用。不搬迁该文件，不拆其中已有的函数，不重排已有导入，不给未改写的函数补注释。
- 整理新写的代码时保持执行顺序、错误处理、兜底覆盖和副作用时机不变，不改变原有逻辑。

## 架构

### 复用与目录

- 新增函数、组件、hook、请求函数或依赖之前，先搜索项目里是否已有同类实现。小幅扩展能满足就扩展，只改本次需要的部分。
- 新代码放进同一层已经承担同类职责的目录。这一层不另开一个缺省名目录。
- 这一层还没有同类目录时，`components/`、`hooks/`、`utils/`、`types/`、`styles/`、`constants/` 按共享范围放：全项目复用的放在源码根下的同名目录；只有一端复用、且 `web/` 或 `mobile/` 已存在的，放在该端目录下的同名目录；只服务一个页面或功能的，放在旁边。
- 根上的旧名字不传到下一层。源码根的工具放在别的目录、而 `web/` 下还没有工具目录时，只被 web 使用的新工具放进 `web/utils/`。
- 仓库还没有 `web/` 和 `mobile/` 时，不新建这两端目录。

### 固定落点

- 接口函数放在源码根的 `api/`。`api/` 只放接口函数。仓库里已经有请求目录时，放进那个目录，不另建 `api/`。
- 被源码 import 的图片、音频、字体、SVG 放在源码根的 `assets/`。favicon、robots.txt 放在仓库根的 `public/`。新增的 `.sql` 放在仓库根的 `db/`。该层已有同类目录时，跟着那个目录。

### 页面

- 非 Next 的新页面放进 `containers/`，路由表放进 `routes/`。该层已有页面目录或路由目录时，跟着那个目录。
- `package.json` 的依赖里有 `next`，且仓库已有 `app/`、`pages/`、`src/app/` 或 `src/pages/`：新页面放进那个已有路由目录，不新建 `containers/`、`routes/`。

### 入口

- `components/`、`hooks/`、`utils/`、`types/`、`constants/`、`api/` 里的内容应在 `index.ts` 统一导出。`index.ts` 只做再导出，不写实现。
- 其他目录从该 `index.ts` 导入，不指向内部文件。同一目录的内容统一导入。
- 该目录已经有别的入口文件时，新导出加进那个文件，不另建 `index.ts`。

### 拆分

- 本次新写的代码根据实际情况进行拆分，并保持原来的执行顺序、错误处理、兜底和副作用时机，不改变原有逻辑，是行数长、职责仍然单一时不拆。不因为已有文件承担了多类职责或叠了多段流程就拆开它。不为了拆而新建没有职责边界的目录。

### 命名

- 已经有稳定命名风格时，新增文件沿用，没有时，新建目录用全小写，多个词用 `-` 连接。代码文件名不套这条。Next 路由里的路由组 `(group)`、动态段 `[id]`、`[...slug]`、`[[...slug]]`、平行路由 `@slot`、拦截路由 `(.)`、`(..)`、`(..)(..)`、`(...)`、私有目录 `_folder` 和 `%5F` 等 nextjs 特殊写法保持框架写法。`page.tsx`、`layout.tsx`、`loading.tsx`、`error.tsx`、`not-found.tsx`、`template.tsx`、`default.tsx`、`route.ts` 等 nextjs 特殊文件名保持框架文件名。
- 同一层已经有稳定命名风格时，新增文件沿用。这一层还没有时，组件和页面组件的文件名、导出名用 PascalCase，且两者相同；自定义 Hook 的文件名和导出名用 `useXxx`，且两者相同；工具函数和只导出一个函数的接口文件，文件名和导出名用 camelCase，且两者相同。同一资源的多个接口函数放在一个 camelCase 文件里。类型和常量文件用 camelCase，类型导出用 PascalCase，常量导出用 `UPPER_SNAKE_CASE`。图片、音频、字体、SVG 和 `.sql` 用全小写，多个词用 `-` 连接。

## 代码

导入、导出、注释、空行和 Promise 规则只覆盖本次新写的代码。旧文件里为接上新代码而新增的导入或导出，按下面的分组插入；该文件里原有的导入和导出保持原样。没有改写的旧函数，不补 JSDoc。

### 导入与导出

- 导入按来源职责分组，路径里同一类目录放在一起。顺序是 `types`、`containers`、`components`、`utils`、`api`、`hooks`、`assets`、`constants`、`styles`、`routes`。`web/`、`mobile/` 或页面旁边的同名目录算同一类。同一类里再按 `PascalCase`、`camelCase`、`UPPER_SNAKE_CASE` 分组，类型导入在值导入前面。组间空一行。第三方包为一组，放在最前。路径里没有这些目录的导入为一组，放在最后。
- 删除确认未使用的导入。保留仅用于副作用的裸导入，例如 `import './setup'`。不改路径别名，不改导入语义。
- 只做再导出的文件同样按命名风格分组。单行导出在前，多行导出在后，组间空一行。不按字符长度重排。

### 注释

新写的函数都写 JSDoc：

- 第一行是摘要，说明行为或时序，不加句号。
- 一个 `@param`一行，中间不空行。写这个参数在这里做什么。没有参数时不写 `@param`。
- 有返回值时写一行 `@return`，写返回的内容，要简单解释一下返回的内容。只有一种结果就写那一种。有多种结果时逐种写明，包括成功、超时、空值和中止。没有返回值时不写 `@return`。

示例：

```ts
/**
 * 等文档加载完，再等页面登记的任务全部结束或超时
 * @param signal 组件卸载时用来中止等待
 * @return 页面任务全部结束时为 true，超时或 signal 已中止时为 false
 */
```
